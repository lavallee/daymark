DaymarkPython · SQLite · MIT

For agents handling a person's projects and life

A task system that simplifies the complexities of real life.

A passport has a deadline; the trip you mean to book on Friday is only a plan. The filter is changed three months after it was last changed. The leak waits on the plumber. Daymark keeps those differences in the record, so an agent can ask what can be done now and trust the answer.

Start in a minute

Requires Python 3.11 or newer. One SQLite file; no cloud, model or account.

uv tool install "daymark-core @ git+https://github.com/lavallee/daymark@v0.3.0"
daymark init
daymark add "Renew passport" --due 2030-05-03 -p 1
daymark add "Book flights" --plan fri --id flights
daymark add "Book hotel" --after flights
daymark add "Water the plants" --every "3 days" --after-completion
daymark ready

daymark prime gives an agent the working rules, the commands and the current state in one call. daymark mcp serves the same verbs to an agent harness over MCP with no extra dependency.

Four kinds of time

A hard deadline, a plan, an earliest start and a soft target mean different things, and only a missed deadline is overdue. Repeats follow a fixed schedule or count from when the work was actually done; skipping a round is not completing it. Dates use a small fixed grammar. Daymark never guesses one.

One rule for what is ready

A task is ready when it is open, its start has arrived, what it depends on is finished, and nobody else has claimed it. Claims lapse on their own, so a crashed session cannot hold work. Notes carry context to the next session, and every change is recorded with who made it.

Suggestions are not commitments

An agent proposes; a person accepts or dismisses. A proposal is never ready work and its reminders stay dormant until it is accepted. A workspace can name who may decide.

Embed it or run it

Use the Python library with a caller-owned SQLite connection to keep task changes inside your application's transaction, or run the optional authenticated HTTP service. Operation identities and expected versions make retries safe and stale writes explicit.

Status

Version 0.3.0. Installed from source or a tagged release; package registry publication is not yet promised. There is no sync between machines. The default reminder worker records outcomes and sends no notifications.
