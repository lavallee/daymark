What can we do now?

Daymark keeps a person's commitments across agent sessions. A deadline, a day you hope to work, and an idea awaiting your decision each get their own place.

Plan an event

It is May 1. The venue needs a deposit by May 8. The invitation needs a draft and an approval. Someone has suggested a poster. Explore the same workspace from four points of view.

What can the agent do?

The draft is planned for tomorrow. The agent can start it today.

$ daymark ready --move agent
draft  Draft invitation  [plan 2030-05-02; move:agent]
What needs the person?

The deposit has a hard cutoff. Approval will appear when the draft is complete.

$ daymark ready --move person
deposit  Pay venue deposit  [due 2030-05-08; move:person]
Where did the poster idea go?

The agenda keeps the suggestion visible until the person decides.

$ daymark agenda
2030-05-02
  draft  Draft invitation  [plan 2030-05-02; move:agent]
2030-05-08
  deposit  Pay venue deposit  [due 2030-05-08; move:person]
PROPOSED, awaiting a decision (1)
  poster  Design a poster  [proposed]
1 more later or undated; see `daymark ready`.
What changes when the draft is done?

Completing the draft releases the approval. The person can review it now.

$ daymark done draft --note "Draft is in the event folder."
$ daymark ready --move person
deposit  Pay venue deposit  [due 2030-05-08; move:person]
approve  Approve invitation  [move:person; after draft]

Try it in an empty folder

Install the CLI with uv and Python 3.11 or newer. The example stores its tasks in a SQLite file in the current folder.

uv tool install "daymark-core @ git+https://github.com/lavallee/daymark@v0.5.0"
daymark init --here
daymark add "Draft invitation" --id draft --plan tomorrow --move agent
daymark add "Approve invitation" --id approve --after draft --move person
daymark ready --move agent

daymark prime gives an agent the working rules, the commands and the current state in one call. daymark mcp serves the same verbs to an agent harness over MCP with no extra dependency.

Four kinds of time

A hard deadline, a plan, an earliest start and a soft target mean different things, and only a missed deadline is overdue. Repeats follow a fixed schedule or count from when the work was actually done; skipping a round is not completing it. Dates use a small fixed grammar. Daymark never guesses one.

One rule for what is ready

A task is ready when it is open, its start has arrived, what it depends on is finished, and nobody else has claimed it. Claims lapse on their own, so a crashed session cannot hold work. Notes carry context to the next session, and every change is recorded with who made it.

Suggestions are not commitments

An agent proposes; a person accepts or dismisses. A proposal is never ready work and its reminders stay dormant until it is accepted. A workspace can name who may decide.

Projects, as plain or as structured as the work needs

A project can be a list of tasks and nothing more. When the work calls for it, a project can add stages for a board, a manual order, item types such as epics, milestones that work belongs to, goals, and typed fields of its own. Each piece is optional and none is enforced. One read returns a whole project as a plan, with a change cursor, so an application can show it as a board or a schedule and write changes back.

Embed it or run it

Use the Python library with a caller-owned SQLite connection to keep task changes inside your application's transaction, or run the optional authenticated HTTP service. Operation identities and expected versions make retries safe and stale writes explicit.

Status

Version 0.5.0. Installed from source or a tagged release; package registry publication is not yet promised. There is no sync between machines. The default reminder worker records outcomes and sends no notifications.
